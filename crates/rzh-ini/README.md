# rzh-ini

The Zero Hour INI engine for [RustZeroHour](https://github.com/RustZeroHour/RustZeroHour):
the `INI` reader ported with its exact semantics, plus the three
migration-plan task-10 validation block types.

- **Origin** (baseline `571a7c5`, Zero Hour configuration, release-build
  branches): `Core/GameEngine/Include/Common/INI.h`,
  `Core/GameEngine/Source/Common/INI/INI.cpp`,
  `Core/GameEngine/Include/Common/GameCommon.h` (frame conversions), and
  for the block types `GeneralsMD/Code/GameEngine/Source/GameLogic/Object/
  {Armor,Locomotor,Weapon}.cpp` with their headers and name lists.
- **Parity**: level **P0** (byte-exact), enforced by the committed golden
  dump in `tests/golden/` (generated by `tools/differential/
  gen_ini_golden.cpp`) and by the upstream `INITest.cpp` tables ported as
  unit tests.
- **Determinism**: `#![forbid(unsafe_code)]`, no global mutable state (the
  `TheXxxStore`/`TheNameKeyGenerator` singletons became explicit values),
  ordered stores only.

## What is ported

- the line reader's byte-level semantics: `;` comments, control
  characters to spaces, the 1028-raw-byte line cap (an over-long
  *physical* line continues on the next read), the synthetic EOF line
  and its line counting;
- `strtok`-compatible tokenizing with per-call separator sets;
- the value scanners with their `std::from_chars` + `strto*` overflow
  behaviour (`scanInt("9223372036854775807") == -1`,
  `scanUnsignedInt("-5") == 4294967291`, prefix parsing of trailing
  junk, `inf`/`nan` words);
- the `initFromINI` field loop: case-sensitive field lookup,
  case-insensitive `End`, silent unknown-field skip (release semantics),
  missing-`End` failure with the original's line counting;
- the block dispatch of `INI::load` and the generic unit conversions
  (durations, velocities, accelerations, angles at the 30 Hz
  logic-frame rate);
- both quoted-string readers with their historical quirks;
- the task-10 validation blocks: complete `Armor`, complete `Locomotor`
  (every field, defaults, `validate`, the forward override chain) and a
  documented representative `Weapon` subset.

## Preserved upstream quirks (pinned by the golden dump)

- redefining an `Armor` always resets every coefficient first, even on
  the override load path;
- redefining a `Locomotor` under a non-override load type parses *over*
  the existing template without clearing it;
- `WeaponStore::newOverride` chains the new template **back** to the old
  one and never registers it, so parsed weapon overrides stay
  unreachable — lookups keep returning the base template (the opposite
  of the Locomotor/ThingTemplate pattern; transcribed as found);
- redefining a weapon without an override load type returns before the
  block is consumed, so the release build fails the file with
  `INI_UNKNOWN_TOKEN` on the block's next line;
- a failed block parse still leaves the (cleared) template in the armor
  store;
- `isEndOfBlock("End")` is false — the original requires at least one
  more character to attempt its comparison.

## Usage

```rust
use rzh_ini::blocks::armor::{ArmorStore, DamageType};
use rzh_ini::{BlockParser, Ini, LoadType};
use rzh_util::NameKeyGenerator;

struct GameData {
    names: NameKeyGenerator,
    armor: ArmorStore,
}

impl BlockParser for GameData {
    fn parse_block(&mut self, ini: &mut Ini, block: &[u8]) -> Result<bool, rzh_ini::IniError> {
        match block {
            b"Armor" => { self.armor.parse_definition(ini, &mut self.names)?; Ok(true) }
            _ => Ok(false), // unknown block: the load fails like the original
        }
    }
}

let mut game = GameData { names: NameKeyGenerator::new(), armor: ArmorStore::new() };
let mut ini = Ini::new();
ini.load("Armor.ini", b"Armor TankArmor\n  Armor = Default 100%\n  Armor = FLAME 50%\nEnd\n".to_vec(),
         LoadType::Overwrite, &mut game).unwrap();

let template = game.armor.find("TankArmor", &mut game.names).unwrap();
assert_eq!(template.adjust_damage(DamageType::Flame, 10.0), 5.0);
```

See `docs/RUST_MIGRATION_PLAN.md` for the porting rules this crate
follows (task 10 of the first ten; the fully typed game data is Phase 2
`rzh-data` work).
