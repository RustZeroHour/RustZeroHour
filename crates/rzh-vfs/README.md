# rzh-vfs

The Zero Hour virtual file system for RustZeroHour (migration plan §3.4,
Phase 1).

## Contents

Everything the engine's data path needs to find and read game files,
ported from the baseline C++ tree (`571a7c5`, Zero Hour configuration,
non-retail branches):

- **`Vfs`** — the local-first overlay (`FileSystem.cpp`): loose files
  shadow archives at instance 0; instance *N* reaches behind them.
  Mounts `*.big` recursively in path-key order (that order fixes which
  archive wins instance 0), including the upstream duplicate-`INIZH.big`
  skip and the mod-loading flow (`loadArchiveFilesFromDirectory`,
  `loadMods`).
- **`big`** — the BIG archive format (`BIGFileSystem.cpp` /
  `ArchiveFile.cpp`): `BIGF` header, big-endian entry table, the
  per-archive directory tree, whole-file (`RAMFile`) and windowed
  (`StreamingArchiveFile`) sub-file reads over the still-open backing.
- **`archive_fs`** — the cross-archive overlay tree
  (`ArchiveFileSystem.cpp`) with the `multimap` file-instance semantics:
  mods mount *in front* (`overwrite = true`), base archives append
  behind.
- **`local`** — the loose-file layer (`Win32LocalFileSystem` behaviour on
  `std::fs`; platform code is re-implemented per plan §1, not
  translated).
- **`ramfile`** — the in-memory sub-file (`RAMFile.cpp`) with its exact
  seek clamping and the `scanInt`/`scanReal`/`scanString`/`nextLine`
  family.
- **`compression`** — the `CompressionManager` dispatch: the `EAR\0`
  payload header family, little-endian uncompressed sizes, and RefPack
  decompression through the byte-exact `rzh-compress` port.
- **`path`** — path keys (`makePathKey`/`comparePath`), the
  `FilenameLess`-ordered `FilenameList` (the order INI files load in),
  and the leaf/extension helpers.
- **`wildcard`** — the `*`/`?` matcher behind every enumeration,
  including its quirks (a trailing `*` never matches an empty remainder).

## Properties

`tests/properties.rs` — the path-key contracts (idempotence, ASCII
case folding, separator equivalence, `FilenameList` dedup) over
generated ASCII paths.

## Parity

**P0 exact** (byte-level), pinned by the golden script
`tests/golden/vfs.txt` — generated by
`tools/differential/gen_vfs_golden.cpp`, a verbatim C++ transcription of
the engine's archive/overlay/routing logic linked against the **real**
EAC RefPack codec. The script covers path keys, orderings, the wildcard
truth table, BIG parsing (including duplicate names, mixed separators
and case), cross-archive listings, instance routing with loose-file
shadowing, overwrite stacking, the INIZH skip, and the
decompress-on-read consumer flow (`CachedFileInputStream`).

## Not ported (yet), with their consumers

- `normalizePath` / `isPathInDirectory` (Win32 `GetFullPathName`
  semantics) — map previews and user paths, Phase 4+.
- The write side of `openFile` (create/truncate, archive copy-out) —
  user-data and map-preview flows.
- `closeArchiveFile` (the `Music.big` hot-swap) — the C++ leaves the
  overlay tree pointing at freed memory (a use-after-free); the unmount
  surface will be redesigned when the audio flow arrives.
- `ENABLE_FILESYSTEM_EXISTENCE_CACHE` — a pure memoization of
  `doesFileExist`; no observable effect for a static mount set.
- The zlib / Nox-LZH / B-tree / Huffman payload codecs — recognised by
  their headers, never carried by Zero Hour data.

## Determinism notes

Data-path code, not simulation code, but the same discipline: no
`unsafe`, no global mutable state (the `TheFileSystem` singletons become
one owned `Vfs`), ordered sets instead of hash iteration, and malformed
archives are `Result` errors where the C++ crashes or reads out of
bounds.
